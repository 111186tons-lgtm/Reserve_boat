# Рабочий процесс Boat Reserve через GitHub

Базовая версия: **V7.2.4**.

## Что хранится в GitHub

- исходный код;
- HTML, CSS и JavaScript;
- изображения и локальные иконки;
- тесты;
- скрипты запуска;
- история изменений;
- безопасный ZIP-релиз без секретов.

## Что никогда не отправляется в GitHub

- `.env` с Telegram-токеном;
- `boat_reserve.db` с рабочими данными;
- административный код и Telegram ID;
- Google OAuth/service-account JSON;
- логи, резервные копии и временные адреса туннелей.

Эти файлы перечислены в `.gitignore`. При `git pull` они остаются на компьютере и не заменяются.

## Обычный цикл работы

1. Меняется только нужный файл или группа файлов.
2. Запускаются тесты.
3. Увеличивается значение в `VERSION`.
4. Изменение фиксируется коммитом и тегом, например `v7.2.5`.
5. GitHub Actions автоматически собирает безопасный ZIP.
6. На рабочем ноутбуке запускается `UPDATE_FROM_GIT.cmd`; `.env` и база сохраняются.

## Сборка ZIP вручную

- `BUILD_RELEASE.cmd` — безопасный ZIP для GitHub, без токена и базы.
- `BUILD_LOCAL_PRIVATE_ZIP.cmd` — локальный настроенный ZIP. Его нельзя публиковать.

## Первичная публикация

Если удалённый репозиторий пуст, запустите `PUBLISH_FIRST_VERSION.cmd`. Git может открыть стандартное окно авторизации GitHub. Скрипт намеренно остановится, если в удалённом репозитории уже есть ветки, чтобы ничего не перезаписать.
