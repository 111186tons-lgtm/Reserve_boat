# Проверенные сценарии V5.2

## Повторное нажатие «Забронировать»

Форма получает один постоянный `idempotency_key`. Пока запрос отправляется, кнопка заблокирована. Если браузер или сеть повторят запрос, сервер вернёт ту же заявку.

Дополнительно сервер ищет точное совпадение по клиенту, катеру, дате, времени, продолжительности и составу гостей за последние 10 минут. Даже с другим ключом новая строка не создаётся.

## «Оплачу позже»

После нажатия:

1. окно оплаты закрывается;
2. открывается раздел «Мои брони»;
3. видна одна сохранённая заявка со статусом «Слот удерживается»;
4. доступна кнопка «Продолжить оплату»;
5. повторно используются та же заявка, то же удержание и те же реквизиты.

Удержание по-прежнему ограничено временем из настройки `hold_minutes`.

## Доступ к диспетчерской

Без кода административные API отвечают `401`. Неверный код не создаёт сессию. Верный код `44444444` выдаёт подписанный токен на ограниченное время.
